# AIMock — модульный обзор агента (вариант 03)

**Статус:** выбранное пользователем направление дизайна, отдельный Draft PR.
База: светлая версия design/light-dashboard-redesign-v1 (PR #23). Не изменять main до согласования.

## Реализовано
На маршрутах #/agent/:id/overview для четырёх демоагентов: consultant, leads, recruiter, support.
- Контекстное меню агента вместо глобального, кнопка «Все агенты».
- Шапка: профессия, описание, демостатус, доступные действия.
- Три модуля: профессия, схема работы (канал → агент → конечное действие), состояние.
- Три показателя, адаптированных под профессию.
- Последние действия и быстрые ссылки на тестирование, журнал и настройки.
- Локальная кнопка «Остановить»/«Запустить»: меняет только состояние в памяти на время загрузки страницы, синхронизирует sidebar и карточку в общем обзоре.
- Попытка открыть настройки работающего агента показывает заглушку: изменение возможно только после остановки.
- Все другие разделы остаются заглушками «В разработке» в той же светлой оболочке.
- Действия «Поделиться», «Дублировать» и «Перенести» явно отмечены как ещё не реализованные.
- HR не может автоматически окончательно отказывать кандидатам.

Все сведения, цифры, интеграции, истории и агенты — демонстрационные. Кнопки не выполняют запросы к API и **не запускают реальные процессы**. Данные не сохраняются.

## Проверить
Запуск: python3 -m http.server 8000.
Маршруты:
- http://localhost:8000/#/agent/leads/overview — утверждённый пример менеджера заявок.
- http://localhost:8000/#/agent/consultant/overview
- http://localhost:8000/#/agent/recruiter/overview
- http://localhost:8000/#/agent/support/overview

Автоматические проверки:
- node --check scripts/agent-detail-modular-v3.js
- node --test tests/light-dashboard.test.mjs tests/agent-detail-modular.test.mjs
- node tests/agent-detail.browser.mjs после установки Playwright и Chromium.

В браузерном тесте проверяются контекстная навигация, все профессии, остановка, запрет редактирования, общая карточка, отсутствие горизонтального переполнения на 1440/1024/768/390. Снимки экрана сохраняются как GitHub Actions artifact agent-detail-variant-03-previews.

Остальные страницы агента (настройки, знания, диалоги, тестирование, логи, интеграции, автоматизации, статистика) пока не реализованы.

В будущей продуктовой версии состояние, права, лимиты и аудит управляются сервером, а не локальным JavaScript.

## Единый полноэкранный каркас (2 ноября)

- Внешний контейнер удалён: интерфейс занимает всю ширину и высоту окна, без серой подложки, рамки и скругления по краям.
- Глобальная верхняя шапка фиксирована к верхней границе; область контента прокручивается обычной прокруткой страницы.
- Боковая панель фиксирована отдельно: отступ слева, сверху и снизу по 16px на больших экранах, небольшой радиус и тонкая тень создают эффект парения.
- На промежуточных экранах панель сужается; на мобильных скрыта и открывается отдельной кнопкой с сохранением отступов и фиксированной шапки.
- Из видимого интерфейса убраны технические идентификаторы агентов, подписи «Модульный обзор», «Карточка агента», «Дизайн-прототип» и маркировки деморежима.
- Это изменение текстов интерфейса **не означает подключение backend**: все цифры и статусы продолжают быть тестовыми. Это прямо зафиксировано в документации, без выдачи их за реальные данные.
- Автоматическая проверка дополнена геометрией viewport, фиксацией header/sidebar, отсутствием служебных строк и круглыми status-иконками; снимки экрана выгружаются из GitHub Actions.

## Точечная переработка деталки (2 ноября)

- У обзора в breadcrumbs выводится только пользовательское имя агента. Для других вкладок сохраняется формат «Имя / Раздел».
- `name` и необязательное `description` являются независимыми от профессии полями; описание выводится только при наличии текста. Пример «Служба помощи» без описания.
- Названия агентов синхронизированы в детальной странице, глобальных карточках, боковом меню и поиске. Используется единый объект исходных данных дизайн-прототипа.
- Теги перенесены под название/описание агента. Из «Профессии» удалены декоративные иконки, теги и «Режим работы / Автоматический». Профессия остаётся отдельной характеристикой.
- «Как работает агент» — три предметных текстовых обязанности для каждой профессии, без случайной визуальной цепочки сервисов. У HR нет автоматического окончательного отказа.
- «Состояние»: доступность, интеграции, материалы; строка о редактировании убрана.
- В карточках показателей увеличен вертикальный интервал между пояснением и переходом.
- Удалён блок «Управление»; «Последние действия» превращены в единую ленту с временем, маркером, названием и контекстом события.
- Меню и остальные ещё не созданные разделы продолжают работать как прежде, остаются заглушками.

**Границы:** изменение имен и пользовательских описаний реализовано как примеры данных в дизайн-прототипе. Редактор, API, реальное хранение и серверное управление агентами в этой ветке отсутствуют.

## Компактные верхние модули

- «Профессия» — минимальная метка, название профессии и короткое пояснение. Нет декоративной графики и лишней высоты.
- «Как работает агент» — три текстовые возможности в лаконичных колонках с тонкими разделителями; при недостаточной ширине перестраивается в вертикальные строки.
- «Состояние» — три компактные строки с иконками состояния. Плотность уменьшена, чтобы карточка не выступала из общего ряда.
- Верхние карточки используют ровную трёхколоночную CSS Grid-сетку и растягиваются до **одной высоты внутри ряда**. Высота определяется самым длинным содержимым, без крупной фиксированной min-height. На узкой ширине карточки располагаются вертикально.
- Добавлены проверки высоты карточек, пустого пространства под последним содержимым и отсутствия прежних нумерованных декоративных элементов.

## Коррекция после обратной связи

Сохраняем исходную геометрию трёх верхних карточек: одинаковая высота и общий ряд на десктопе. Меняем только текстовое наполнение двух блоков; разные высоты из промежуточной версии отменены. Browser smoke проверяет совпадение top/bottom и порядок карточек в строке.
