# AIMock — Аудит карточки агента по архитектуре v6

Дата сопоставления: 27 октября 2026. Источник: приложенный архив `AIMock_Current_Approved_Architecture_PDF_2026-10-26_v6(1).zip` (13 PDF). Данный файл фиксирует полноту **визуального прототипа**, а не готовность production-разработки.

## Что выявлено после первоначальной проверки

Прежний PR #14 покрывал вкладку «Настройки», но ошибочно пропустил утверждённый самостоятельный контракт `12_Sharing_Copying.pdf` (9 страниц, версия 1.0). В `01_Product.pdf`, `11_Frontend_Engineering.pdf`, а также в Backend/API, Data/Database, Workflow и Admin содержатся сквозные зависимости Share/Copy. Поэтому первоначальная формулировка о полном охвате архитектуры была неверной.

## UI и безопасность

- Интерфейс prototype не делает фальшивых share-token, не публикует ссылку и не копирует объекты. Копируется только **ссылка на локальный предпросмотр** с явной маркировкой.
- Публичный preview получает лишь ID разрешённых иллюстративных материалов. Он не загружает HR-анкеты, персональные данные, диалоги и настоящие секреты.
- Для реального копирования обязательны аккаунт/Workspace, ACL, server preflight, динамические квоты для всех не удалённых агентов/Workflow (включая draft/stopped), функциональная дедупликация, целостность пакета и повторная проверка при commit.
- Косметическая правка имени/обложки не даёт право создать дубль. Новые копии — независимые inactive drafts; исходный объект не останавливается, не удаляется и не передаёт токены.
- Заявленные «разрешённые материалы» в UI пока **фиктивные макетные позиции**, а не действительный ответ ACL.
- В `11_Frontend_Engineering.pdf` указано, что production frontend должен быть Next.js / TS / MobX / SCSS Modules с FSD; текущий design-agents — чистый HTML/CSS/JS reference, а не готовая реализация.

## Приоритет следующей работы

1. Визуально согласовать две кнопки карточки и оба попапа, а также публичную read-only карточку.
2. Зафиксировать UX-состояния: share forbidden/expired/revoked, auth, quota BLOCKED, ALREADY_EXISTS, needs reconnect, model unavailable и точный server preview.
3. Отдельно проработать Workflow Sharing/Copying и HR editor вакансий. Сверить каталог со всеми шестью профессиями.
4. После Stage-Gate создать технические issues для серверного протокола preview/commit, статусов, контроля доступа, транзакций и тестов. Не обозначать UI-прототип как завершённую backend-функцию.

Вариант «Обзор» агента остаётся ранее утверждённым, а «Настройки» и Share/Copy пока **на согласовании**.
